## What Armory is

Armory is the open-source, agent-native **registry of every harness component** — MCPs, skills, hooks,
sub-agents, identity files, memory patterns, rules, CLIs, eval frameworks, observability, infrastructure, and
the workflows that compose them (12 categories, ~25,000 components). One armory an agent reaches into to grab
exactly the gear it needs. _For agents, by agents, of agents._ Live: `armory-murex.vercel.app`.

## The ONE rule that prevents 90% of mistakes

**Two different things live in this repo. Never confuse them.**

| | Armory's OWN harness (install it to use Armory) | The catalog (what Armory aggregates) |
|---|---|---|
| Paths | `armory-mcp/` · `armory-skill/` · `cli/` · `.claude-plugin/` etc. | `mcps/ skills/ subagents/ workflows/ hooks/ claudemd-rules/ clis-tools/ evals/ observability/ infrastructure/ memory/ identity/` + `brain/` + `catalog.json` |
| Count | exactly **one** of each (prefixed `armory-*`) | **~25,000** components from many sources |
| Edit by hand? | yes (it's our code) | **no** — it's generated/aggregated data |

`armory-mcp/` (our one server) ≠ `brain/components/mcps/` (the ~21,000 we catalog). `armory-skill/` (our one
skill) ≠ `skills/` (the ~1,100 we catalog). Our gear is `armory-*`; everything else at root is catalog data.

## Hard rules (non-negotiable)

1. **Never hand-edit `catalog.json`.** It is generated by `pnpm catalog` (`ingest/catalog.mjs`). Edit the
   source in `brain/` (the Obsidian metadata graph — the source of truth), then regenerate.
2. **Additive only.** New components enter through the pipeline, never by deleting/overwriting existing ones.
   Provenance (`source_repo`, `license`, `stars`, `verified_at`) and `related:` links must be preserved.
3. **Every candidate passes the Hamel test-gate before it enters** (`ingest/test-gate.mjs`) — functional +
   behavioral — so cataloged skills can't drift or go stale.
4. **No single source is special.** Anything under the catalog folders / `brain/` / harness dot-folders is
   aggregated from many upstreams; don't privilege one.

## Setup & commands

```bash
pnpm install              # Node >=18, pnpm@9 (see package.json)
pnpm catalog              # regenerate catalog.json from brain/ (ingest/catalog.mjs)
pnpm validate             # schema + integrity checks (ingest/validate.mjs)
pnpm build                # pnpm catalog && pnpm -r build (workspaces, incl. web/)
node ingest/test-gate.mjs # Hamel functional+behavioral gate a component must pass to enter
```

The ingest machinery lives in `ingest/` (crawlers, promote, catalog, validate, test-gate, surface);
`incoming/` is **ephemeral** staging (gitignored); `repos/watchlist.json` is the source-repo watchlist;
`autolab.yml` is the nightly remote cron that self-evolves the registry (Darwin [DSIP](./dsip.json)
Performance-Novelty selection — no laptop needed).

## How to add a component (the additive path)

1. Add/curate its detail page under `brain/components/<type>/<slug>.md` (frontmatter + `[[wikilinks]]`).
2. Drop the installable file at the matching root folder (`mcps/<slug>.json`, `skills/<slug>/…`, etc.).
3. Run `node ingest/test-gate.mjs` → must pass (functional + behavioral).
4. `pnpm catalog` to regenerate the index, then `pnpm validate`.
5. Commit. (Don't hand-edit `catalog.json` — step 4 produces it.)

## Repo map (five zones)

- **Component types** — `mcps/ skills/ subagents/ workflows/ claudemd-rules/ hooks/ clis-tools/ evals/ observability/ infrastructure/ memory/ identity/` (installable files; metadata → `brain/components/<type>/`).
- **The brain** — `brain/` (Obsidian source of truth) → `catalog.json` (generated index, never hand-edited).
- **Armory's own harness** — `armory-mcp/ armory-skill/ cli/ .claude-plugin/ .codex-plugin/ .hermes-plugin/ opencode.json .mcp.json install.sh`.
- **The machinery** — `ingest/ incoming/ repos/ autolab.yml dsip.json`.
- **Site + docs** — `web/` (→ armory-murex.vercel.app), `docs/`, `scripts/`.

## Install Armory into your own agent

- CLI: `npm i -g @namanparikh/armory` → `armory search <q>` · `armory install <name>` (fetches the real thing via `gh`/git).
- MCP: package `armory-mcp` (`search_components` / `get_component` / `submit_component` over stdio).
- Skill: `armory-skill/` teaches an agent when + how to reach into the registry.
- Plugin: one-install bundle for Claude Code / Codex / OpenCode / Gemini / Hermes (`.claude-plugin/` etc.; see `PLUGIN.md`).
