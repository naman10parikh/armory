# Armory — Repo Structure

The whole repo in one map. **Every root folder is listed here with a one-line purpose**, grouped into five zones. Counts grow nightly (AutoLab) — `catalog.json` is the authoritative number, never the prose here.

---

## Zone 1 · Component types — each harness component is its own root folder

These are the 12 canonical component types. **This is "every element of a harness, its own folder."** Each `<type>/` at the root holds the installable files (or generated install configs); the full metadata for each entry lives in `brain/components/<type>/`.

| Root folder | Holds | ~Count |
|---|---|---|
| `mcps/` | MCP server install configs (`<slug>.json`) — generated by `ingest/surface.mjs` | ~21,850 |
| `skills/` | `SKILL.md` files (real vendored gear) | ~1,130 |
| `subagents/` | sub-agent definitions | ~730 |
| `workflows/` | slash-command + composition recipes | ~716 |
| `claudemd-rules/` | CLAUDE.md / .cursorrules rule packs | ~467 |
| `hooks/` | lifecycle hook scripts + configs | ~140 |
| `clis-tools/` | agent-native CLIs & tools | ~91 |
| `infrastructure/` | sandboxes, runtimes, payment rails | ~52 |
| `evals/` | eval frameworks | ~38 |
| `observability/` | tracing / logging / cost tools | ~36 |
| `memory/` | memory-layer patterns | ~4 |
| `identity/` | SOUL / persona specs | ~3 |

> The folder names match `brain/components/<type>/` **exactly** — generators depend on this, so the names are fixed.
> "Plugins" as a harness concept = the MCP/connector substrate (`mcps/`) wired in via the install configs in Zone 3 — there is no separate `plugins/` catalog type.

## Zone 2 · `brain/` — the catalog's source of truth (its own universe)

```
brain/
  components/
    mcps/        <slug>.md     ← MCP detail pages (~21,850)
    skills/      <slug>.md
    subagents/   <slug>.md
    hooks/       <slug>.md
    workflows/   <slug>.md
    claudemd-rules/ <slug>.md
    clis-tools/  <slug>.md
    evals/       <slug>.md
    observability/  <slug>.md
    infrastructure/ <slug>.md
    identity/    <slug>.md
    memory/      <slug>.md
  MOC - Armory.md             ← master index note
catalog.json                  ← generated index at the repo root (never hand-edited)
```

`brain/` is an **Obsidian vault**: markdown + YAML frontmatter + `[[wikilinks]]`. One source of truth → the site, the MCP server, and the CLI are all generated from it. Rebuild the index with `node ingest/catalog.mjs`.

**Where are the MCP details?** → `brain/components/mcps/<slug>.md`.

## Zone 3 · Armory's own harness — install Armory itself

```
armory-mcp/                   ← the Armory MCP server (search_components / get_component / submit_component)
armory-skill/                 ← the `armory` skill (teaches an agent when to reach into the registry)
cli/                          ← the `armory` CLI (armory search / armory install)
.claude/                      ← Armory's OWN working harness (the skills/hooks it runs with)
.claude-plugin/  .codex-plugin/  .hermes-plugin/   ← per-harness plugin manifests
.cursor/  .codex/  .opencode/  .gemini/            ← per-harness install drops / configs
opencode.json  .mcp.json                            ← MCP server wiring
install.sh  install.ps1                             ← auto-detect harness + wire armory-mcp
```

`armory-mcp/` (our **one** server) ≠ `mcps/` (the ~21,850 we catalog). `armory-skill/` (our **one** skill) ≠ `skills/` (the ~1,130 we catalog). See [HARNESS.md](./HARNESS.md) and [PLUGIN.md](./PLUGIN.md).

## Zone 4 · The machinery — grow + self-improve

```
ingest/
  crawl-*.mjs    ← per-source adapters (smithery, glama, mcpso, pulsemcp, wshobson, awesome-cc, ecc, …)
  promote.mjs    ← dedupe incoming/ → brain/components/
  catalog.mjs    ← walk brain/components/ → catalog.json
  validate.mjs   ← frontmatter contract check (hard gate)
  test-gate.mjs  ← Hamel L1 functional + L2 behavioral gate (anti-drift)
  surface.mjs    ← generate root mcps/ + catalog-view folders from brain/
  verify-links.mjs
incoming/                     ← ephemeral, GITIGNORED crawl staging (see incoming/README.md)
repos/                        ← source-repo watchlist the loop keeps tabs on (watchlist.json + crawl-repos.mjs)
.github/workflows/autolab.yml ← nightly self-improvement loop (the productized AutoLab)
dsip.json                     ← Darwin Self-Improvement Protocol contract
AUTOLAB-LOG.md                ← audit trail of every self-improve run
MASTER-TODO.md                ← tracked work items
```

## The one rule that prevents confusion

| Prefix / path | What it is |
|---|---|
| `armory-*`, `cli/`, the dotfolders | Armory's **own** gear (the tool that runs the show) |
| `brain/` | catalog metadata + detail pages (source of truth) |
| the 12 type folders (`mcps/ skills/ …`) | the catalog laid out as **installable files**, one folder per component type |
| `ingest/` + `incoming/` + `repos/` | the machinery that grows + self-improves the registry |
| `web/ docs/ scripts/` | the website + human docs + dev helpers |

No duplicate "components" names. `brain/components/` = catalog detail pages; the real installable files live in the type folders at the repo root.
