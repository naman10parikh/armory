## What this is

Armory — the agent-native registry of every harness component (MCPs, skills, hooks, sub-agents, …; 12
categories, ~25,000 components). _For agents, by agents, of agents._ Live: `armory-murex.vercel.app`.

## The ONE rule (read first)

**Two different things live here — never confuse them:**

- **Armory's own harness** = `armory-mcp/`, `armory-skill/`, `cli/`, `.claude-plugin/` (prefixed `armory-*`).
  Exactly one of each. This is our code — editable.
- **The catalog** = `mcps/ skills/ subagents/ workflows/ hooks/ claudemd-rules/ clis-tools/ evals/
  observability/ infrastructure/ memory/ identity/` + `brain/` + `catalog.json`. ~25,000 aggregated
  components — **data, not our code.**

`armory-mcp/` (our one server) ≠ `brain/components/mcps/` (the ~21,000 we catalog).

## Hard rules

1. **Never hand-edit `catalog.json`** — it is generated by `pnpm catalog` (`ingest/catalog.mjs`). Edit `brain/`
   (the Obsidian source of truth), then regenerate.
2. **Additive only** — add/enhance; never delete cataloged components or strip provenance/`related:` links.
3. **Test-gate before entry** — every new component must pass `node ingest/test-gate.mjs` (Hamel
   functional + behavioral) so cataloged skills can't drift or go stale.
4. **No single source is special** — catalog folders / `brain/` / harness dot-folders are aggregated upstreams.
5. **Surgical changes** — minimum diff, match existing style, conventional commits. Generated folder READMEs
   come from `ingest/surface.mjs` — regenerate, don't hand-tweak.

## Commands

```bash
pnpm install              # Node >=18, pnpm@9
pnpm catalog              # regenerate catalog.json from brain/
pnpm validate             # schema + integrity checks
pnpm build                # pnpm catalog && pnpm -r build (incl. web/)
node ingest/test-gate.mjs # the gate a component must pass to enter
```

To add a component: curate `brain/components/<type>/<slug>.md` → drop the file at the matching root folder →
`node ingest/test-gate.mjs` → `pnpm catalog` → `pnpm validate` → commit. (See `AGENTS.md` for the full path.)

## Self-evolution

`autolab.yml` is a nightly remote cron that discovers new sources (Darwin [DSIP](./dsip.json)
Performance-Novelty selection), test-gates each candidate, dedups, validates, and commits — the armory
restocks itself. No laptop needed.
