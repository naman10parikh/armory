# Armory

> The ranked, agent-native index of open-source building blocks for the agent stack — MCP servers, CLIs, skills, plugins, hooks, sub-agents, rules, repos, packages, docs. Every ranked component carries one **Universal score** (0-100), so you can ask for the best or trending tool in a domain and get a cited answer instead of a web search.

## What it is for

The first stop to find a tool, not a general web search. As of {{as_of}}, computed from `catalog.json` when the site is built (never hand-typed): **{{total}}** components cataloged · **{{ranked}}** ranked (hold at least one real signal) · **{{tested}}** test-verified · {{types}} component types · {{domains}} domains · {{verticals}} industry verticals.

## CLI

Not yet on npm — `npm view @namanparikh/armory` and `npm view armory-mcp` both 404 as of 2026-09-26. Build from source: `cd cli && pnpm build`, then run `node dist/index.js <command>` (shown below as `armory <command>`, the name once published).

| Command | Does |
|---|---|
| `armory search <query> [-c type] [-d domain] [-n N] [--json]` | keyword-rank by name/desc/tags — same scorer as `/api/search` |
| `armory get <name>` | print one component's full markdown (frontmatter + body) |
| `armory rank [-c type] [-d domain] [-s axis] [--asc] [-n N] [--json]` | Universal-score leaderboard — same engine as `/api/rank` |
| `armory install <name> [-c cli] [--to dir] [-f] [--dry-run]` | fetch + wire a component into a harness (fuzzy-matched name) |
| `armory init [--claude\|--cursor\|--codex\|--opencode\|--gemini] [--to dir] [-f] [--dry-run]` | wire the `armory-mcp` server into a harness's MCP config |
| `armory submit -f <path>` | validate frontmatter, copy into `incoming/<name>.md` |
| `armory list [-t type]` | counts + names, optionally filtered to one type |

## The score

`universal = 0.8 × base + 0.2 × others` — `base` is the row's single strongest percentile; `others` is its second strongest (0 if none). One signal caps at 80; a third signal counts only when it beats one of the first two, so more evidence never lowers a score. A recorded 0 is no signal. No real signal → honestly unranked.

Five signals, each percentiled within its own **kind** (github-root / github-file / registry / package / website) — not against everything: `tested` (eval_score, binary today) · `mentions` (credited by URL only; a name match alone is never enough) · `stars` (repo roots only: a file inside a repo never borrows its parent's) · `usage` (non-GitHub registries only, never mixed with stars) · `forks` (repo roots only). `pushed_at` is metadata, never scored — it only breaks ties and sets the `stale` flag (no push in 24 months). Full arithmetic + worked examples: `/formula`.

## Parameters

- `component`: {{component_counts}} — counts as of {{as_of}}
- `infra`, `cli`, `tool` and `workflow` list only rows made for that job: running agent code in isolation, commands run from a terminal, and routing, scheduling or looping agent work. `fit` names the job and counts the rows filed there but left out (`fit.left_out`); search and an unfiltered rank still include them.
- `domain`: front-end · back-end · database · auth · browser · payments · devops · observability · comms · search · ai-agents · github-vcs · other (keyword-matched, not curated)
- `vertical`: finance · legal · healthcare · e-commerce · marketing · education · gaming · productivity · data-analytics · security · devtools · ai-infra (null = industry-agnostic)
- `sort`: universal (default) · popular (usage ?? stars) · tested · practitioner (mentions) · stars · name

## Submit a component

1. `armory submit -f file.md` (CLI) or MCP `submit_component` (raw markdown) validates the required frontmatter (`name, type, description, source_url, license`) against the 12-category contract and writes into `incoming/<name>.md`. **Local write only — no PR, no network call.**
2. Or a human opens a PR adding `brain/components/<type>/<slug>.md` directly; CI validates frontmatter and rebuilds `catalog.json`.
3. `ingest/test-gate.mjs` grades L1 functional (schema) + L2 behavioral (non-trivial desc/body/tags) — deterministic pass/fail gate.
4. `ingest/promote.mjs` dedupes staged `incoming/<source>/` stubs (by name+type, or globally by normalized name+type with a source-priority tiebreak) into `brain/components/` — dry-run by default; a real write needs both `--apply` and an explicit `--to`.
5. `ingest/catalog.mjs` walks `brain/components/` and rebuilds `catalog.json` — the only path from a submitted file to something `/api/rank`, the CLI, and the MCP server can see.

`scripts/crawl-to-pr.mjs` is a separate, opt-in automation: it turns the freshness crawler's own discoveries into stubs and, only with `--apply --pr` (and `gh` installed), runs steps 3-5 and opens a real GitHub PR. `armory submit` itself never opens a PR — it only writes locally.

## Pages

| Page | Shows |
|---|---|
| `/` | home — search bar + top-20 leaderboard |
| `/leaderboard` | every ranked component, filter/sort by component · domain · vertical · axis; calls `/api/rank` |
| `/browse` | plain catalog browse |
| `/ask` | conversational front door, POSTs to `/api/ask` |
| `/c` | the catalog grouped into the 11 canonical harness components |
| `/c/{component}` | one canonical component's pick + its ranked rows (11 static slugs) |
| `/stack` | one recommended pick per component, in assembly order — JSON twin `/api/stack` |
| `/e/{type}/{slug}` | one component's detail page (`type` = raw catalog folder, e.g. `mcps`) |
| `/formula` | how the Universal score works, rendered live from the same engine as the API |
| `/status` | freshness & coverage report for the whole index |
| `/pipeline` | "Pipeline": the layers the catalog is built from (sources, types, the Score, verticals, query surfaces), computed from `catalog.json` when the site is built. `/graph` and `/timeline` redirect here |

## Examples

- Best front-end tools: `GET /api/rank?domain=front-end`
- Top browser MCP: `GET /api/rank?component=mcp&domain=browser`
- Most-used/forked payments tools: `GET /api/rank?domain=payments&sort=popular`
- Keyword search: `GET /api/search?q=browser+automation`
- Natural language: `POST /api/ask {"q":"finance mcp for excel"}`
