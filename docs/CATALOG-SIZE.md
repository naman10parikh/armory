# `catalog.json` is 52.6 MB — the ruling (CP138 T24)

**Decision: gzip it to `catalog.json.gz` and decompress at load. Not tonight.** Measured 2026-09-07.

## What is actually true

| | |
| --- | --- |
| `catalog.json` | **52.6 MB** — over GitHub's 50 MB soft recommendation (the hard limit is 100 MB) |
| gzipped | **6.9 MB — 87% smaller** |
| commits that have touched it | **136** |
| repo pack | **226 MB** |
| source of truth | **`brain/components/**/*.md` — 64,859 markdown files.** The JSON is derived |

The 50 MB warning is the symptom, not the disease. The disease is that a **derived** 52 MB artifact is
regenerated by the nightly autolab and committed, so the repository grows by a fresh revision of it
every night. 136 revisions is most of that 226 MB pack, and the curve is linear from here.

## Options considered

| Option | Effect | Cost |
| --- | --- | --- |
| **gzip → 6.9 MB** ✅ | kills the warning, cuts pack growth ~8×, artifact stays in git so the deploy is unchanged in shape | one read site in `lib/rank.mjs`, plus `scripts/copy-data.mjs` and the web build |
| Git LFS | removes blobs from pack history entirely | every clone and the Vercel build need LFS configured; a build that silently gets an LFS pointer instead of data fails in a confusing way |
| Stop committing it; build at deploy | conceptually correct — derived artifacts do not belong in git | building from 64,859 markdown files at deploy time, on every deploy |
| Split into 12 per-component files | each file under the limit | same total bytes, and every consumer changes |
| Accept and document | zero work | pack keeps growing ~52 MB of revisions per night |

## Why not tonight

Changing how the catalogue is read touches the hot runtime path shared by the site, the CLI and the
MCP server — and **production is currently returning 402 `DEPLOYMENT_DISABLED` account-wide (CP138
C-07)**, so a deploy cannot be verified as a user. Shipping a data-path change that cannot be tested
end-to-end is the exact thing the QA rule exists to stop. The measurement is the deliverable; the
change lands in the first session after prod is reachable, in this order:

1. `ingest/catalog.mjs` writes both `catalog.json.gz` and (transitionally) `catalog.json`
2. `lib/rank.mjs` prefers the `.gz`, falls back to the plain file
3. `scripts/copy-data.mjs` and the web build vendor the `.gz`
4. verify: `armory rank`, the MCP `rank_components`, and `/api/rank` on prod all return the same top
   row for the same query as they do today (`letta-ai-letta`, 99, memory)
5. only then stop writing the plain file, and `.gitignore` it

**Do not rewrite history to shrink the pack.** It breaks every existing clone and the nightly
autolab's checkout for a one-time gain that step 5 makes permanent anyway.
